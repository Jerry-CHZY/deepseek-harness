# Agent Note: Web token-usage readout

Status: implemented

English | [中文](2026-09-20-web-token-usage-readout.zh.md)

## Problem

The Web GUI's composer statistics row reports a conversation's token usage as one total-token pill with a cache-hit share; the four disjoint billing buckets exist only behind that pill's dialog, so a reader who wants the classification has to click for it. The harness has no money figure anywhere, while the terminal front end already shows its own session cost estimate in its footer. A Web reader who wants "what did this conversation cost, and what was it made of" has neither in one place.

## Decision

**A separate, removable plugin.** `@deepseek-ai/dsh-client-ui-token-usage` is a pure UI plugin — its node half is an empty `apply()` so the row exists in the Loader, and its browser half registers one `conversation.composer.dock` entry (`id: 'token-usage'`, order 10, after the chat statistics pills). The web-app bundle mounts it by its own row, so removing that row removes the readout without touching `ui-chat`.

**Per-conversation counts come from the durable projection.** The entry reads `useProjection('tokenUsage')`, whose four buckets are disjoint and fold the complete durable log, so paging and compaction cannot change them; the slot's `scope: 'session'` is what makes the counters per-conversation. The line leads with the session total, then renders uncached input, output, and whichever cache buckets are non-zero, in compact counts (517 / 12.3K / 1.2M), and closes with the context occupancy — `projectedTokens` over `pressureTokens`, against the newest advertised capacity — when the meter has both; zero cache buckets are dropped because they carry no information and only widen the row. The accessible label names all four buckets including the zero ones.

**Cost is a configured estimate, not a bill.** The entry resolves the session's `modelSelection` projection (preferring `lastUsed`, the route the billed usage came from, over `next`) against the plugin's `pricing` config: CNY per million tokens keyed by model-id prefix, longest matching prefix winning. The estimate bills uncached input plus cache writes at the miss rate, cache reads at the hit rate, and output at the output rate. An unpriced model shows counts with no cost figure rather than a guessed one, and sub-fen amounts keep micro-precision instead of rounding to zero. Defaults are the advisory DeepSeek official peak-rate table; deployments override them through the row config.

**Pricing reaches the browser through a host-registered projection.** The plugin's node half registers the configured table as the `tokenPricing` session projection; the browser component reads it with `useProjection('tokenPricing')`. Browser plugin rows carry no `config`, so a client-half `Config` would be defaults-only and the row's `config:` block would silently do nothing; the projection seam is the existing delivery path for host-owned values the browser renders, and it keeps the host row's `config:` authoritative.

**Installation backfills the money the readout never saw.** A second node-half projection, `tokenCostBackfill`, folds `request/header` events into whether the session used a priced route, which routes the resolved backfill table misses, and the report path derived from `SessionHeader.cwd`; the browser component renders a locale-owned notice under the readout whenever a route is unpriced. The pass itself is an effect-owned asynchronous side effect, never part of activation: it resolves `ctx.sessionQuery` optionally through `ctx.get`, reads each archived log with `readSession`, folds peak and off-peak usage per settlement — an `assistant/message` or a failed `assistant/attempt`, whose usage arrives either in the event's own field or as the last `usage` chunk of its embedded stream — buckets each sample by its own event timestamp in Beijing time, prices the two periods separately, and writes `<cwd>/TOKEN_COST.md` through a temporary file plus a rename. Within one turn and step a later settlement replaces the earlier one, except that `llm/retry-started` closes that replacement slot so the attempt after a retry adds to the one it followed. A marker comment carrying the fold-semantics version, the price-table hash, and every folded session watermark makes a restart rewrite nothing, and bumping that version rewrites every report an older fold produced. A directory whose routes are all unpriced gets the routes plus a pasteable `backfill.pricing` row instead of a guessed amount, and a session with no `cwd` is logged and skipped rather than written to a fallback path.

**The package installs itself into a profile.** `package.json` declares `dsh.bundle.patch` pointing at the shipped `cordis.patch.yml`, so `dsh plugin --profile <name> add <tarball>` records a direct profile dependency and mounts the row from the package instead of relying on the web-app bundle. Both carriers insert the same `ui-token-usage` id, which the Loader resolves to one entry. The install path runs `scripts/pack-local.mjs`: it stages a copy outside the workspace, rewrites workspace ranges and drops `devDependencies` — a workspace `pnpm pack` leaves `workspace:` in `devDependencies`, which a profile install rejects — and `--name` rewrites the build-time bundle id and style-tag ids so a personal-scope release loads under its published name.

**`/usage` answers on two surfaces, neither of which calls the provider.** A row config names the command (default `usage`). Clients that execute commands run the registration: the node half registers it under `ctx.inject(['commands'], …)`, so a profile without a command surface keeps the readout and the backfill instead of holding the plugin pending, and the handler returns the report as command text. Clients that can only send a message reach the `llm/stream` middleware, which matches a whole text block of the newest human message — the harness's instruction, context, and skill-catalog messages are user-role messages with other `source.kind` values, so injections cannot match — and answers with one text block and `stop`. That stream carries **no usage sample**: the loop omits the event field when a stream reports none, while the token meter takes its context-occupancy numerator from the newest settlement, so a synthetic zero would read as an empty context. Both surfaces assemble the report from the session's own `tokenUsage`, `modelSelection`, `contextPressure`, and `tokenPricing` states; a session whose projections are unavailable falls through to the provider (or fails the command) unchanged.

## Alternatives considered

**Extending `ui-chat`'s `UsagePill`.** The pill already owns the durable total and the cache-hit share, and its dialog already lists the four buckets. Adding cost there would couple a user-facing pricing table to the chat package and keep the classification click-only; the request was an independently mountable readout, and a second dock row leaves the existing pill's reading intact.

**A host-side `tokenCost` projection.** A host fold could price each usage sample with the route that produced it and bucket it by the event's peak/off-peak hour, which the client cannot do from aggregate buckets. It would have to duplicate `dsh-token-meter`'s attempt-replacement and retry fold, and pricing is not a host-owned seam: no package publishes token prices. Deferred until a pricing seam exists; the installation backfill above later took the `request/header` route fold and the settlement replacement it describes, but it prices a report rather than projecting a live cost, and it still prices a session by its last route.

**Merging the readout into the chat statistics row.** Composing two packages' content into one entry needs a runtime value dependency between feature plugins, which the client export discipline forbids; slots are the crossing point, and a sibling entry is the sanctioned form.

## Consequences

The classification is exact for the whole durable log, and the cost figure is as good as the configured table: one rate prices the conversation because the projection carries no per-sample timestamps, and one route prices it because `modelSelection.lastUsed` is the newest consumed route. Both limits are stated in the package README. The readout repeats the pill's total tokens in classified form; that duplication is the point of the request, and the pill remains the exact-integer surface. The backfill's report carries the per-settlement split the readout cannot, but it inherits the same single-route limit and only counts settlements whose provider reported usage; and because it folds the stored logs itself rather than reusing a projection cache, every start re-reads the whole archive, a cost the README states. `pnpm --filter @deepseek-ai/dsh-client-ui-token-usage test` covers the pricing arithmetic (longest-prefix resolution, the miss/hit/output formula, the unlisted-model rule), the rendered classification and cost presence rules (including an absent `tokenPricing` projection), the host projection units and their registration, the peak-window bucketing, the settlement replacement rule with its retry and stream-embedded-usage cases, a full backfill pass over temporary working directories (amounts table, pricing instructions, marker idempotency and fold-version invalidation, missing `cwd`, unreadable session, aborted pass, failed write), and the browser half's registration, dictionary pairing, and fiber-teardown disposal.
